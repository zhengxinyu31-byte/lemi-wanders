# storymap 交互链路全景对齐表

> 目的：把 storymap（+ bilibili BV13LEu6fEAZ 视频）的**全部交互链路**拆成「主链路 / 支链路 / 交互方式」，
> 逐条对齐 Lemi demo 现状，标注差距与本轮动作。这是 demo 重建的施工蓝图。
> 说明：storymap 讲「人物」，Lemi 讲「故事线」，做主客体反转（人物→故事线、足迹→POI、一生时间轴→路线行程）。

---

## 一、根因反思（为什么"效果差异巨大"）

| 差距 | storymap 实际 | 我 demo 之前 | 影响 |
|---|---|---|---|
| **地图是假的**（最致命） | 真实地图瓦片（MapLibre/GeoVis + 真实街道/河流/地名/缩放平移） | 手绘抽象 SVG 色块，河流街道随手画 | 路线对不上真实地理，像卡通示意图 |
| **配图是假的** | 真实照片 / 海报 | 渐变色块写文字 | "准确配图"完全落空 |
| **地图交互缺失** | 可拖拽/缩放/惯性、marker 真实叠加、InfoWindow | SVG 静态，靠 CSS transform 假装 panTo | 没有"真地图"的操作感 |
| **动线精度** | 轨迹沿真实路网、panTo 平滑、逐段生长贴合真实距离 | 直线连点、距离是像素估算 | 动线不可信 |
| 巴黎项目本身 | —— | app.js 其实**已在用 MapLibre+CARTO**，我却退回 SVG | 方向性错误 |

**结论**：交互逻辑我做了七八成，但"真实地图 + 真实配图"两个底座塌了，导致观感崩塌。本轮必须换真地图 + 真配图，并把交互链路逐条对齐。

## 五、本轮施工顺序（据上表）

1. **换真实地图底座**（M1/M2/M3/M4/B1/B2）：MapLibre GL + CARTO positron 底图 + 7 POI 真实经纬度。左右双栏的右栏 = 真 MapLibre。城市地图视角 = 真 MapLibre。
2. **真实路线 + 真 marker**（B2/M4/M5）：GeoJSON LineString 连真实坐标；每 POI 一个真实 Marker（序号徽标）。
3. **真配图**（B3/B11/M11）：每 POI 挂 Wikimedia 真实照片 URL + `onerror` 兜底为雅致占位。
4. **真 panTo + 逐段生长**（B7/B8/B9/M3/M5/M12）：自动播放用 `map.easeTo` 逐站移镜（仅超出视野才移，克制）；route line 用 line-dasharray/逐段 setData 生长；停留时长按**真实地理距离** haversine 计算。
5. **底图切换真影像**（B10/M9）：矢量=positron，影像=CARTO/ESRI 卫星栅格源切换。
6. **联动 + 浮卡 + 空白关卡**（B4/B5/B6/M6/M7）：真 marker ↔ 时间轴双向；点 marker 弹 popup；点地图空白关闭。
7. **保留已达标项**：搜索/键盘/hash/aria/reduced-motion/世界地图/主题标签。
8. **补齐小项**：故事线卡作品 chip（S4）、marker hover（M14）；全屏/导出/考点/纠错列 P2 视情况。
