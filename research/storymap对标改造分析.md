# storymap 对标改造分析

> 目标：完整拆解 storymap（github: cuizicheng1024/storymap，参考 bilibili BV13LEu6fEAZ）常规模式的全部交互逻辑与功能点，
> 逐条对照 Lemi's Diary 现状，判定「纯静态站能不能做」，给出「必须做哪些改造」。
> 本轮方向：**暂不考虑游戏模式，常规模式全面对标 storymap 人物页 / 首页动线**。
> 数据来源：storymap 源码通读（首页 `index.html`、人物页 `profile_page.html`、构建器 `builder.py` 等，均带行号）+ Lemi 现状（`web/assets/app.js`、v2 spec）。

---

## 0. 对标方法论：主客体反转（先立框架）

storymap 讲「**一个人的一生**」，Lemi 讲「**一座城的一条故事线**」。两者信息架构高度同构，只需把「主体」从"人物"换成"故事线"，把"一生的时间维度"换成"路线的行程维度"：

| storymap 主体 | → | Lemi's Diary 主体 | 说明 |
|---|---|---|---|
| 人物 person | → | 故事线 storyline | 一条故事线 = 一个"人物页" |
| 一生时间轴（生卒 / 年龄 / 生命阶段） | → | 路线行程动线（站点顺序 / 路程距离） | 时间维 → 空间行程维 |
| 足迹地点 location（古名/今名/事件/停留） | → | POI / StoryStop（POI × 故事线） | 结构几乎一一对应 |
| 人物关系图谱 relatedGraph | → | 共享 POI 跨故事线关联 | "相关人物" → "也讲到这里的其它故事线" |
| 时空对话（LLM 实时扮演人物） | → | 追问卡（构建期预设问答） | ⚠️ 后端能力，静态降级 |
| 考点 / 教材知识点 | → | 实用信息 / 拍照机位 / 城市 tips | 知识补充块 |
| 首页人物星图（时间×空间分布 + 时间窗滑块） | → | 首页城市 Hub（故事线卡片墙 / 城市地图分布 / 主题标签） | 时间维筛选 → 主题/城市维筛选 |

**一句话结论**：storymap 的「人物页 journey-shell 双栏联动」几乎可以 1:1 搬到我们的「故事线页」，这是本次最大、也最值得投入的改造；首页则做「星图→城市 Hub」的降维改造；时空对话、实时生成两块因无后端必须降级。

## 1. 首页 Hub 改造（对标 storymap 首页四视角）

storymap 首页 = 搜索框 + 时间分布关系图 + 时间窗滑块 + 空间分布地图 + Story Console（Agent 工作台）。逐条对照：

| # | storymap 功能点（带源码定位） | Lemi 现状 | 纯静态可行 | 必要改造动作 | 优先级 |
|---|---|---|---|---|
| 1.1 | **搜索框 + 联想下拉**：打分匹配（本名/别名/外文/拼音 × 精确/前缀/模糊，`index.html:5104-5159`），Top8，命中原因标签（`:2536-2551`），"暂未生成"徽标（`:5184`），键盘上下/回车/Esc（`:5312-5338`） | ❌ 完全没有搜索 | ✅ 可做（构建期出静态索引 + 前端匹配） | **新建搜索**：对 POI/名人/名作建静态索引；联想下拉带类型+摘要+命中原因标签+"待收录"徽标+键盘导航。**去掉拼音打分**（中文城市专名为主，保留中英文名+别名+内容命中即可） | **P0** |
| 1.2 | **作品 chip + hover tooltip**：搜索结果每条挂最多 3 个作品 chip，悬浮出作品摘要（`:5178-5183`、`:2484-2535`） | ❌ 无 | ✅ 可做 | 搜索结果条挂"关联故事线/关联作品" chip（对应我们的名作/故事线），可选 hover 摘要 | P1 |
| 1.3 | **时间分布关系图（Canvas 星图）**：节点按活动年份×身份泳道布局，朝代配色，关系连线，太阳特殊人物（`:6544-6563`、`:3421-3542`） | ❌ 无 | ⚠️ 可做但**语义不匹配**：我们没有"一生时间"维度 | **不直接复刻**。改为「**故事线卡片墙**」作默认视角（海报+标题+关联作品+POI 数）。星图的"节点关系"降级为 1.6 主题标签聚合 | P0（以卡片墙替代） |
| 1.4 | **时间窗滑块 + 朝代预设**：双滑块拖动筛选年代区间，朝代快捷按钮（`:3103-3133`、`:2895-2909`） | ❌ 无 | ⚠️ 语义不匹配 | **不做时间窗**。故事线无"年代"主维；改为「**主题/标签筛选**」（文学/影视/历史/美食/建筑）承接"筛选"心智 | P1 |
| 1.5 | **空间分布地图（高德）**：省份落点 marker、按省搜索、各省 Top5 曲线、坐标缓存 + WGS84/GCJ02 转换（`:5818+`、`:5931-6031`） | ⚠️ 有 MapLibre 但只画单条线路径 | ✅ 可做（MapLibre + CARTO，无需 GCJ02 转换） | **新建"城市地图分布"视角**：城市地图打点展示全部 POI，按所属故事线着色；点位浮卡→跳对应故事线的该站。**用 MapLibre 而非高德**（境外城市 + 已在用），WGS84 直用无需偏移转换 | **P0** |
| 1.6 | **Story Console / 橙子 Agent 工作台**：像素进度面板、阶段流水线、Agent 卡片、运行时状态板（`:1912-2015`、`:3801-3954`） | ❌ 无 | ❌ 依赖后端实时生成任务 | **不做**（这是"实时生成未收录人物"的可视化，我们纯静态无生成任务） | 放弃 |
| 1.7 | **后端准入 + 生成流程**：precheck / generate / pollTask / 断点恢复（`:4532-4992`） | ❌ 无 | ❌ 必须后端 | **放弃**，作为"未来接后端"钩子写进 Roadmap | 放弃/Roadmap |
| 1.8 | **分层加载**：核心索引先加载、重字段 idle 补载、地图懒初始化（`:6494-6591`、`:5818`） | ❌ 单文件一次性加载 | ✅ 可做 | **必要改造**：首页轻量索引（故事线卡/POI 名/坐标）先出，长文摘要+图片 `requestIdleCallback` 补；地图进视口才 init | P0 |
| 1.9 | **URL 初始聚焦**：`?person=` / `localStorage` 决定初始高亮（`:5216-5229`） | ❌ 无 | ✅ 可做 | 首页支持 `?storyline=` / `?poi=` 深链定位 | P1 |
| 1.10 | **埋点（GA + APM）**（`:10`） | ❌ 无 | ✅（可选） | 首期可不做，留钩子 | P2 |

**首页改造小结**：搜索（1.1）、城市地图分布（1.5）、故事线卡片墙（1.3 替代方案）、分层加载（1.8）为 **P0 四件套**；时间窗/星图因"无时间维"改为主题标签筛选；Story Console / 生成流程整块放弃（后端）。

## 2. 故事线页改造（对标 storymap 人物页 journey-shell —— 本次重点）

这是 storymap 最精华、也和我们最同构的部分。人物页 = journey-shell 双栏（时间轴 × 地图）+ 自动播放 + 底图切换 + 地点详情浮卡 + 时空对话 + 关系图谱 + 考点。逐条：

| # | storymap 功能点（带源码定位） | Lemi 现状 | 纯静态可行 | 必要改造动作 | 优先级 |
|---|---|---|---|---|
| 2.1 | **journey-shell 双栏骨架**：左时间轴 × 右地图，可拖拽分割、全屏、导出态（`profile_page.html:10747-10760`） | ⚠️ 仅单栏 Scrollama 滚动 + 顶部地图 | ✅ 可做 | **核心改造**：改为「左站点行程列表 × 右路线地图」双栏；桌面左右分栏，移动端上下（地图 sticky 顶部 ~40%） | **P0** |
| 2.2 | **时间轴事件卡**：序号徽标（按生命阶段配色）、地名（古名:今名）、年龄/阶段/事件类型徽标、停留时长、生命进度条、事件描述（`:10844-11007`） | ⚠️ 有 POI 卡（序号+名+四类叙事+机位） | ✅ 可做 | **对齐字段**：站点卡 = 序号 + POI 名 + 四类叙事摘要 + 拍照机位 + 停留/步行提示；"生命阶段配色"→"故事线章节配色"；"古名:今名"→保留（很多巴黎地名有中译名/原名） | P0 |
| 2.3 | **时间轴 ↔ 地图 双向联动**：点卡片→地图定位、点 marker→详情卡、地图空白→关闭卡（`:6180+`、`:6321-6379`、`:11039-11063`） | ⚠️ 仅"滚到哪 flyTo 到哪"单向 | ✅ 可做 | **核心改造**：做成**双向**——点站点↔点地图互相高亮定位 | **P0** |
| 2.4 | **镜头策略：panTo 不 flyTo**（明确产品决策，防眩晕，`:6338-6346`；"仅目标不在可视区才平移"`:6339`） | ⚠️ 现用 flyTo | ✅ 可做 | **必须改**：把 spec 里的 `flyTo` 改为 **panTo（仅超出视野才平移）**，与 storymap 一致防眩晕 | **P0**（已在 spec 修正） |
| 2.5 | **自动播放**：逐站推进，**停留时长按站间 haversine 距离** `clamp(dist/3, 1200, 3200)ms`（`:7229-7252`）；到末站自动停 | ❌ 无 | ✅ 可做 | **新建自动播放**：一键播完整条线，停留时长按站距动态算（直接采用 clamp 公式思路） | P0 |
| 2.6 | **轨迹逐段生长动画** `startSegmentTransition`（播放 1150ms / 手动 820ms，`:4975-5001`）；passed/current/future 段差异化配色（`:6416-6469`） | ❌ 无（路径一次性画全） | ✅ 可做 | **新建**：轨迹沿路线逐段生长；已过/当前/未来段差异着色（旧段偏白淡出） | P0 |
| 2.7 | **键盘导航 + aria-live 无障碍**：←→上一/下一站、Home/End 首末站，切站向 `#aria-live` 播报"第 N 站，共 M 站"（`:6259-6310`、`:6200-6234`） | ❌ 无 | ✅ 可做 | **必要改造**：加键盘导航 + aria-live 播报（无障碍达标，storymap 做得很完整值得抄） | P1 |
| 2.8 | **URL hash `#loc=N`**：`replaceState` 不刷 history，分享/刷新还原（`:6187-6199`） | ⚠️ v2 spec 提过 `#stop=3` | ✅ 可做 | 对齐：`#stop=N` 用 replaceState 写入，刷新/分享恢复 | P0 |
| 2.9 | **底图切换**：矢量/影像/地形/3D，三地图栈（GeoVis/AMap/Cesium）逐级回退（`:11206-11216`、`:8843-8921`） | ❌ 单一 CARTO 底图 | ⚠️ 矢量+影像✅；地形/3D 成本高 | **改造**：只做**矢量 + 影像双底图**（MapLibre + 卫星瓦片）；**不做地形/3D**（三地图栈回退是 storymap 最大复杂度来源，性价比低） | P1 |
| 2.10 | **全屏 + 导出图片**：全屏 journey-shell，`getDisplayMedia` 屏幕共享所见即所得导出（`:9654-9686`、`:11217-11230`） | ❌ 无 | ✅ 可做（浏览器 API） | **可选增强**：全屏查看 + 导出行程图（分享钩子）。首期可不做，留 Roadmap | P2 |
| 2.11 | **地点详情浮卡**：地名+事件+配图（可开大图）+ 历史意义 + 名句/作品（作品带 tooltip）（`:11244-11296`） | ⚠️ 侧栏卡片已展开四类叙事 | ✅ 可做 | 对齐：地图点位弹浮卡（POI 名 + 四类叙事 + 图片 + 拍照机位），点图可放大 | P0 |
| 2.12 | **时空对话（LLM 扮演人物）**：@多人同台、情绪指示、场景感知 system prompt、SSE 流式、本地档案降级（`:9770-10453`） | ❌ 无 | ❌ 真实回复必须后端 LLM | **降级为追问卡**：每 POI 挂 2-3 张构建期预设、经交叉验证的问答卡（"为什么值得来/怎么拍好看/有什么趣闻"），点击展开。实时对话作为后端钩子写进 Roadmap | P0（降级方案）|
| 2.13 | **推荐追问卡（纯前端规则引擎）**：画像打分 + 定制表 + 真实地名注入生成推荐问题（`:9943-10148`，**不依赖 LLM**） | ❌ 无 | ✅ **可做**（这是纯前端！） | **可直接借鉴**：追问卡的"问题"可用类似规则（结合真实 POI 名/首个名作生成），但**答案**必须构建期预生成（storymap 答案靠 LLM，我们靠预设） | P1 |
| 2.14 | **关系图谱**：相关人物左右分列、点击跳转、进对话 @ 候选（`:11587-11651`） | ⚠️ spec 有"共享 POI 跨线关联"占位 | ✅ 可做 | 对齐：POI 卡上"其它故事线也讲到这里"= 关系图谱的降维（同一 POI 跨故事线跳转）；首期 1 线占位，多线点亮 | P1 |
| 2.15 | **考点/知识点模块**：教材知识点 + 考点，展开收起（`:11567-11585`） | ❌ 无 | ✅ 可做 | 映射为「实用信息 / 城市 tips」块（开放时间/交通/周边），可选 | P2 |
| 2.16 | **内容纠错反馈**（mailto 报错模板，`:11655-11664`） | ❌ 无 | ✅ 可做 | 可选：加"内容纠错"入口（mailto/表单），呼应"内容可信"定位 | P2 |
| 2.17 | **朝代动态主题**：注入 `--color-dynasty-*` CSS 变量、`html[data-dynasty]`（`:9876-9894`） | ❌ 无 | ✅ 可做 | 映射为**「因城气质皮肤」**：`html[data-city]` + 城市主题 token（巴黎浪漫皮肤），机制同构 | P1 |
| 2.18 | **reduced-motion 降级**：关闭动画、flyTo 降为无动画（`:602`、`:8533`） | ❌ 无 | ✅ 可做 | **必要**：`prefers-reduced-motion` 时自动播放/逐段生长降级为直接跳转 | P1 |
| 2.19 | **地图懒初始化**：进视口才 init，正文/时间轴优先渲染（`:6711-6717`） | ❌ 无 | ✅ 可做 | 必要：地图进视口再初始化 | P1 |

**故事线页改造小结**：双栏骨架（2.1）+ 双向联动（2.3）+ panTo 镜头（2.4）+ 自动播放（2.5/2.6）+ hash 记忆（2.8）+ 地点浮卡（2.11）+ 追问卡降级（2.12）为 **P0 核心**；键盘/无障碍/关系图/主题/reduced-motion 为 P1；地形3D/全屏导出/考点/纠错为 P2 或放弃。

## 4. 数据模型改造（对标 storymap builder 数据结构）

storymap 数据模型（D 节）与我们三层模型（POI / StoryStop / StoryLine / City）高度同构，需补齐的字段：

| storymap 字段 | → | Lemi 对应 / 需补字段 | 说明 |
|---|---|---|---|
| `person{name, foreignName, description, quote, dynasty, aliases[], highlights{works[]}}` | → | `StoryLine{title_zh/en, 关联作品, 简介, 主题标签[], 别名[]}` | 故事线需补：主题标签、别名（供搜索）、关联名作/名人 |
| `location{name, ancientName, modernName, lat, lng, type, event, time, duration, significance, works[], quoteLines[], poster{png}}` | → | `StoryStop / POI{name_zh/en, lat, lng, 四类叙事, 拍照机位, 停留提示, 关联名作, 经典台词, 图片}` | POI 需补：停留/步行提示（供自动播放算时长）、经典台词（拍立得/浮卡用）、古今地名（可选） |
| `mapStyle{pathColor, markers{}}` | → | `City theme token{主色/辅色/地图样式/点缀}` | 城市主题 token（见 2.17） |
| `relatedGraph{nodes[]}` | → | 共享 POI 跨故事线索引 | 由三层模型 POI 被多故事线引用天然派生 |
| `search_keys[] / search_tokens[] / search_pinyin[]` | → | 构建期搜索索引（去 pinyin，加中英文名+别名+内容 token） | **新建**：搜索索引文件 |
| `has_story`（是否已生成） | → | `待收录` 标记 | 未收录 POI/故事线的占位标记 |
| 首页 `stellar_home_data.json` + `_detail.json`（核心+重字段分离） | → | 首页轻/重索引分离 | **新建**：支撑分层加载（1.8/3.3） |

**数据模型改造小结**：三层模型骨架无需重构，主要是**补字段**（搜索索引、主题标签、停留提示、经典台词、待收录标记）+ **拆分层加载的轻/重索引文件**。

## 5. 必须放弃 / 降级的功能（后端依赖，划清边界）

| storymap 功能 | 为何放弃/降级 | 我们的处理 |
|---|---|---|
| 时空对话（LLM 实时回复） | 真实回复必须后端 LLM（`api/ai/proxy`） | **降级**为构建期预设「追问卡」；实时对话列为后端 Roadmap 钩子 |
| 未收录人物实时生成 | 必须 FastAPI `generate/task` | **放弃**；未收录内容打"待收录"徽标 |
| Story Console / 橙子 Agent 工作台 | 是生成任务的可视化 | **放弃** |
| 运行时状态板 `health/ready` | 后端健康检查 | 放弃 |
| 坐标回填 `coords/bulk` | 后端写回 | 放弃（我们坐标构建期备齐） |
| 地形 / 3D 底图（Cesium）+ 三地图栈回退 | 复杂度极高、性价比低 | **放弃**，只做矢量+影像 |
| 高德 AMap + GCJ02 坐标偏移 | 境内地图方案 | **放弃**，用 MapLibre + WGS84（境外城市无需偏移） |

## 6. 改造优先级汇总（P0 → P2）

**P0（首期必做，撑起"对标 storymap"的骨架）**
- 首页：搜索（联想下拉+命中原因+待收录徽标）、城市地图分布视角、故事线卡片墙、分层加载
- 故事线页：左右双栏骨架、时间轴↔地图**双向**联动、**panTo** 克制镜头、自动播放（按站距算时长）+ 轨迹逐段生长、地图点位浮卡、`#stop=N` hash 记忆、追问卡（对话降级）
- 全局：确立静态能力边界、路由/深链
- 数据：搜索索引 + 轻/重索引拆分 + 补字段（停留提示/经典台词/待收录标记）

**P1（体验完整度，storymap 做得好值得抄）**
- 键盘导航 + aria-live 无障碍、reduced-motion 降级、地图懒初始化
- 矢量+影像双底图切换
- 因城气质皮肤 token（巴黎浪漫）、主题标签筛选视角
- 共享 POI 跨故事线关联（多线后点亮）、作品 chip

**P2（增强/可选）**
- 全屏 + 导出行程图、实用信息/tips 块、内容纠错入口、埋点、性能基线报告

**放弃（后端依赖 / 性价比低）**
- 时空对话实时回复、未收录实时生成、Story Console、地形3D、高德+GCJ02

## 7. 与 bilibili 视频（BV13LEu6fEAZ）的呼应

视频合集呈现的核心亮点（李白轨迹自动播放 / 和李白聊天 / 动态地图 / 多 Agent 协作）对应：
- **李白轨迹自动播放**：= 我们的自动播放 + 轨迹逐段生长（P0，2.5/2.6）——这是视频最抓人的一幕，必须做好。
- **动态地图（时间轴↔地图联动）**：= 双向联动 + panTo 克制镜头（P0，2.3/2.4）。
- **和李白聊天**：= 时空对话，**后端依赖**，我们降级为追问卡（2.12）。
- **多 Agent 协作 / 生成**：= Story Console + 生成流程，**放弃**（后端）。

> 结论：视频里"看得见、纯前端能复刻"的高光（自动播放长动线 + 地图联动 + 底图切换 + 关系跳转）我们全部纳入 P0/P1；"需要后端"的高光（聊天、实时生成）划到 Roadmap，用追问卡/待收录徽标承接体验。
