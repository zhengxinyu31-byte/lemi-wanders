# 需求 Spec：Lemi's Diary 常规模式（对标 storymap · 含搜索）

> **本轮方向（Round 8 调整）**：
> 1. **删除昼夜切换模式**——全站不再区分昼/夜两阶段。
> 2. **全面对标 storymap（参考 bilibili BV13LEu6fEAZ），暂不考虑游戏模式**——常规模式为本轮唯一主体。
> 3. 基于 storymap 全量交互功能点，完成「必要改造分析」并据此定义常规模式。
>
> 首期落地范围：1 城市（巴黎）× 1 故事线（《艾米莉在巴黎》）。
> 相关文档：[storymap 对标改造分析](../research/storymap%20对标改造分析.md)｜[游戏模式后续规划（暂缓）](../roadmap/游戏模式后续规划.md)

## 1. 背景与目标

### 需求来源

- 已有 v1（静态信息清单）实测过于「数据库视角」，交互单薄。
- 常规模式现状仅有「单条故事线滚动叙事」，**缺首页 hub、缺搜索、缺多故事线浏览、缺时间轴×地图双栏联动**。
- storymap 的「人物页 journey-shell 双栏联动 + 首页多视角 hub + 本地索引搜索」与本产品高度同构，本轮以其为蓝本，把常规模式升级为可浏览、可检索、体验完整的文化地图产品。

### 主客体反转（对标基线）

storymap 讲「一个人的一生」，Lemi 讲「一座城的一条故事线」——信息架构同构，只需把主体从「人物」换成「故事线」，把「一生的时间维」换成「路线的行程维」：

| storymap | → | Lemi's Diary |
|---|---|---|
| 人物 person | → | 故事线 storyline |
| 一生时间轴（生卒/年龄/阶段） | → | 路线行程动线（站点顺序/路程距离） |
| 足迹地点 location | → | POI / StoryStop（POI × 故事线） |
| 人物关系图谱 | → | 共享 POI 跨故事线关联 |
| 时空对话（LLM 实时扮演） | → | 追问卡（构建期预设问答，静态降级） |
| 首页人物星图（时间/空间分布 + 时间窗） | → | 首页城市 Hub（故事线卡片墙 / 城市地图分布 / 主题标签） |

### 业务目标

1. **常规模式对标 storymap**：从「只有单条滚动页」升级为「首页 hub（卡片墙 + 城市地图 + 搜索 + 主题标签）→ 故事线页（时间轴 × 地图双栏联动 + 自动播放）」的完整体验。
2. **纯静态可落地**：搜索/浏览/双栏联动/自动播放全部在纯静态站内实现；实时对话、实时生成明确划为后端钩子，不在本轮。
3. **可扩展**：首期单城单线，但信息架构按「可扩展到多城多线」设计，避免二次返工。

### 成功指标

- 用户能通过搜索命中 POI / 名人 / 名作，并顺利进入常规模式看到对应内容。
- 故事线页双栏联动顺滑、镜头克制无眩晕；一键自动播放能完整、流畅地走完整条线（对标视频里「李白轨迹自动播放」的高光体验）。
- 量化指标：首期以体验跑通为主，暂无硬性数值目标。

## 2. 用户与场景

### 目标用户

出境游的文史爱好者：既想「出发前种草、幻想旅程」，也想「到达地标时看到别人看不到的那一层」。重「好看好逛 + 内容可信」，非行程工具。

### 核心场景

| 场景 | 用户状态 | 需求 |
|---|---|---|
| 出发前躺着刷 | 做梦、种草 | 浏览故事线卡片墙 / 地图分布，被内容种草 |
| 巴黎地铁上 | 碎片时间 | 搜索此刻这里，快速拿到谈资 |
| 站在花神门口 | 已到达 | 进故事线页看到别人看不到的那一层 |

- **mobile-first 为硬要求**（后两个场景均在手机上）。

## 3. 功能需求

> 功能设计逐条对标 storymap，并标注纯静态可行性。完整对照见 [storymap 对标改造分析](../research/storymap%20对标改造分析.md)。

### 3.1 常规模式 · 首页 Hub（世界地图为主入口 + 多视角）

> 对标 storymap 首页「搜索 + 时间分布星图 + 时间窗 + 空间地图」，做主客体反转。因故事线无「年代」主维，星图/时间窗改为「世界地图 / 卡片墙 / 主题标签」。

- **功能描述**：常规模式入口页，以**世界地图**为主入口，承载「选城市 → 多视角浏览 + 搜索」。顶部常驻搜索框 + 全站统计条（如「N 城 · M 条故事线 · K 个 POI」）。
- **浏览视角（业务规则）**：
  1. **世界地图（默认主入口）**：一张世界地图打点展示已收录/待收录的城市（巴黎为首期唯一可进入城市，其余城市以剪影 + 「待解锁」占位）；点击城市 → 进入该城市的浏览视角（卡片墙/城市地图/主题标签）。这是"选城市"这一层的主入口，也天然支撑多城市扩展。
  2. **故事线卡片墙**：进入城市后展示其故事线大卡（海报 + 标题 + 关联作品/名人 + 简介 + POI 数），点击进入该故事线页。（对应 storymap 星图，降维为卡片墙）
  3. **城市地图分布**：地图打点展示该城市所有 POI，按所属故事线着色区分；点位浮出内容卡，可跳到「对应故事线的该站」。（对应 storymap 空间分布地图，改用 MapLibre + WGS84，无需坐标偏移转换）
  4. **顶部常驻搜索**：见 3.2。
  5. **主题 / 标签浏览**：按内容标签（文学/影视/历史/美食/建筑等）聚合 POI 与故事线，点标签筛出相关内容。（对应 storymap 时间窗筛选，改为主题维）首期少量标签起步，随内容增长丰富。
- **视角层级**：世界地图（选城市）为顶层；进入城市后，卡片墙/城市地图/主题标签通过 Tab 互切，搜索框全程常驻可用。
- **分层加载（业务规则 · 对标 storymap）**：首页优先加载轻量核心索引（故事线卡 / POI 名 / 坐标），重字段（长文摘要、图片）`requestIdleCallback` 空闲补载；地图进视口才初始化。
- **深链**：支持 `?storyline=` / `?poi=` 初始定位（对标 storymap `?person=`）。
- **可扩展性**：按「可扩展到多城市 / 多故事线」设计信息架构，首期仅巴黎单城单线有真实内容，其余以占位/空态呈现。

### 3.2 常规模式 · 搜索

> 对标 storymap 首页本地索引搜索（打分匹配 + 联想下拉 + 命中原因标签 + 未生成徽标）。去掉拼音打分（境外城市专名为主），保留中英文名 + 别名 + 内容命中。

- **功能描述**：首页搜索框输入关键词，实时联想并跳转到相关内容，纯前端本地索引匹配。
- **搜索覆盖对象（业务规则）**：**POI 地点 / 名人 / 名作**三类。名人 / 名作按叙事内容（scene/anecdote/masterpiece/history 等文本）建立索引命中。
- **联想与结果呈现（业务规则 · 对标 storymap）**：输入即出**联想下拉**——
  - 匹配优先级：名称精确 > 别名精确 > 名称前缀 > 别名前缀 > 名称模糊 > 内容命中（对标 storymap `scoreNodeMatch` 分级，去 pinyin 层）。
  - 每条结果显示：名称 + 类型（POI/名人/名作）+ 一句摘要 + **命中原因标签**（如「名称精确」「别名」「内容命中」）+ 关联内容 chip（关联的故事线/作品）。
  - **键盘导航**：↑↓ 循环高亮、Enter 跳转、Esc 关闭（对标 storymap）。
  - 未收录/未生成内容的结果打**「待收录」徽标**，可见但点击给「敬请期待」提示，不进入空页。
- **命中后动线（业务规则）**：命中结果点击后**进入常规模式**并按类型呈现——
  - **命中 POI** → 进入常规模式，展示该 POI 相关卡片 / 内容（定位到其所属故事线的对应站，高亮地图点）。
  - **命中名人 / 名作** → 进入常规模式，展示与之相关的 POI（该名人/名作关联的地点）。
- **能力边界（业务规则 · 已确认）**：**搜索仅限已生成的静态内容**。纯静态站、无后端，搜索在构建期产出的静态索引内做前端本地匹配，**不做实时生成、不做 LLM 问答/对话**（对标 storymap 静态版边界）。
- **无结果兜底**：未命中时给出空态提示 + 可回到浏览（故事线卡片墙 / 地图 / 主题标签）。

### 3.3 常规模式 · 故事线页（时间轴 × 地图 双栏联动）—— 本轮核心

> 直接对标 storymap 人物页 journey-shell（左时间轴 × 右地图双栏 + 自动播放 + 底图切换 + 地点浮卡）。这是本产品与 storymap 最同构、最值得投入的部分，也是视频里「动态地图 + 轨迹自动播放」高光的落地。

- **功能描述**：只读呈现一条故事线的沿途内容，左「站点行程时间轴」× 右「路线地图」双栏联动。
- **双栏骨架（业务规则）**：桌面左右分栏（可拖拽分割），移动端上下——地图收为顶部 sticky（约 40%），下方为站点列表滚动；触控目标 ≥ 44px。
- **左栏 · 站点行程时间轴（业务规则）**：
  - 按路线顺序排列各站卡片：**序号徽标 + POI 名 +（可选中译/原名）+ 四类叙事摘要 + 拍照机位 + 停留/步行提示 + 事件描述**（对齐 storymap 事件卡字段，"生命阶段配色"→"故事线章节配色"）。
  - 顶部控件：「自动播放 / 停止」「上一站 / 下一站」。
  - 时间轴节点/连线区分「已过 / 当前 / 未来」站（对标 storymap `is-passed/is-future`）。
- **右栏 · 路线地图（业务规则）**：按站点顺序连成平滑曲线路径，站点打点；点位可弹出地点浮卡。
- **双向联动（业务规则 · 对标 storymap，本次核心改造）**：
  - 点左栏站点 → 地图定位到该站并弹出内容卡；
  - 点地图点位 → 左栏对应站高亮并滚动到视图；
  - 点地图空白 → 关闭浮卡。
- **镜头策略（业务规则 · 对标 storymap 明确决策）**：用 **panTo（仅目标超出可视区才平移）**，**不用 flyTo / setBounds**，避免频繁大跳导致眩晕。
- **自动播放（业务规则 · 对标视频高光）**：一键播放整条线——
  - 镜头逐站推进（panTo）；轨迹沿路线**逐段生长**动画；
  - **停留时长按站间距离动态计算**（对标 storymap `clamp(距离/3, 1200ms, 3200ms)` 思路，站距越大停越久）；
  - 已过 / 当前 / 未来段差异化着色（旧段偏白淡出）；
  - 到末站自动停止；末站再点播放则回到首站重播。
- **地图底图（业务规则）**：提供**矢量 + 影像**双底图切换（MapLibre + 卫星瓦片）。**不做地形 / 3D**（storymap 三地图栈回退复杂度过高、性价比低）。
- **地点详情浮卡（业务规则）**：地图点位/站点触发浮卡——POI 名 + 四类叙事 + 图片（可点开大图）+ 拍照机位 + 历史意义/名句。
- **内容呈现（业务规则）**：POI 只读展示四类叙事（剧情/轶事/名作/历史）+ 图片 + 拍照机位 + 经典台词/名句。**本轮不做追问卡**；实时对话/问答整体作为「后续可接后端」钩子，本轮不涉及。
- **共享 POI 跨故事线关联（业务规则）**：POI 卡上预留「其它故事线也讲到这里」区块（对标 storymap 关系图谱降维）——同一 POI 出现在别的故事线时可点击跳转；首期仅 1 线，显示占位（「敬请期待」），多线后自动点亮。三层数据模型天然支持。
- **无障碍 + reduced-motion（业务规则 · 对标 storymap）**：
  - 键盘导航：←→ 上/下一站、Home/End 首/末站；
  - `aria-live` 播报「第 N 站，共 M 站：地点」；
  - `prefers-reduced-motion` 时自动播放/逐段生长降级为直接跳转、不做动画。
- **状态记忆**：URL hash 记住当前站（`#stop=N`，用 replaceState 不刷 history），刷新/分享可恢复（对标 storymap `#loc=N`）。
- **地图懒初始化**：地图进视口才初始化，正文/时间轴优先渲染。
- **POI 呈现方式（已确认）**：**不新增独立 POI 详情页**，POI 内容通过锚定到故事线页中的对应站来呈现。
- **叙事内容**：只读展示四类叙事（剧情/轶事/名作/历史）+ 图片 + 拍照机位 + 经典台词；不显示进度/集卡角标（游戏元素不进常规模式）。

### 3.4 静态能力边界（对标 storymap 静态版 vs 全功能版）

- **纯静态可用（本轮范围）**：首页浏览 / 搜索 / 世界地图选城市 / 城市地图分布 / 故事线页双栏联动 / 自动播放 / 底图切换 / 地点浮卡 / 共享 POI 关联 / 深链分享——全部无后端可用。
- **明确划为后端钩子（本轮不做）**：实时对话（LLM 扮演/时空对话）、追问卡问答、未收录内容实时生成、Story Console/Agent 工作台、运行时健康状态、坐标回填。未收录内容以「待收录」徽标承接。

## 4. 页面与交互

### 4.1 主用户旅程

- **核心链路**：进入常规模式首页 Hub（**世界地图选城市** → 卡片墙/城市地图/搜索/主题标签视角）→ 搜索或浏览 → 故事线页（左时间轴 × 右地图双栏联动 + 自动播放）。
- **页面间关系**：首页 Hub（世界地图 → 城市多视角）→ 故事线页（POI 以锚点承载，不新增独立 POI 页）。
- **全局交互规则**：语言开关全局共享（localStorage `lang`，中/英双语）；常规模式纯只读不写玩家状态；mobile-first；无障碍与 reduced-motion 全局贯彻。

### 4.2 常规模式首页 Hub（世界地图 + 城市多视角）

- **页面用途**：多视角浏览与检索入口，以世界地图为选城市主入口。
- **核心元素**：顶部常驻搜索框 + 全站统计条；顶层世界地图（选城市）；进入城市后视角切换 Tab——故事线卡片墙 / 城市地图分布 / 主题标签浏览。
- **用户操作流程**：① 世界地图点城市进入（非首期城市为「待解锁」占位）；② 卡片墙点故事线进入故事线页；③ 城市地图点 POI 浮卡 → 跳对应故事线的该站；④ 搜索 POI/名人/名作 → 联想下拉 → 按类型跳转；⑤ 点主题标签筛出相关内容。
- **状态与反馈**：轻量索引先加载、重字段空闲补载；地图进视口再初始化；搜索无结果空态；「待收录」内容打徽标。

### 4.3 常规模式故事线页（双栏联动）

- **页面用途**：只读呈现一条故事线，左时间轴 × 右地图联动。
- **核心元素**：左栏站点行程时间轴（含自动播放/上下站控件、追问卡）；右栏路线地图（曲线路径 + 站点 + 矢量/影像双底图）。
- **用户操作流程**：点站点 ↔ 点地图 双向联动（panTo 定位、弹卡/高亮）；一键自动播放走完整条线（轨迹逐段生长、按站距算停留时长）；点「其它故事线也讲到这里」跳转（首期占位）；从搜索命中 POI 进入时直接锚定对应站并高亮。
- **状态与反馈**：当前站高亮；`#stop=N` hash 记忆，刷新/分享可恢复；键盘导航 + aria-live 播报；reduced-motion 降级为跳转不动画；移动端地图顶部 sticky。

### 4.4 设计风格 / 视觉基调（因城定制）

> 核心原则：**风格随城市气质走**——同一套交互框架，换城市即换「皮肤」，让用户一眼感到「这就是巴黎/东京/……」。机制对标 storymap「朝代动态主题」（`html[data-dynasty]` + CSS 变量），改为 `html[data-city]` + 城市主题 token。

- **统一底子（跨城一致）**：旅行手账 / 复古明信片质感；圆角卡片、纸张纹理感、邮戳/贴纸式点缀；思源黑体（标题）+ 思源宋体（正文叙事）+ 手写体（仅经典台词/名言，可空）。
- **因城气质皮肤（每城一套 theme token）**：一座城市配一组「主色 + 辅色 + 字体气质 + 地图样式 + 点缀元素」，可扩展。
  - **巴黎 ·《艾米莉在巴黎》= 浪漫气质**：
    - 主色调：香槟金 / 玫瑰粉 / 塞纳河灰蓝，低饱和、柔和，营造浪漫复古感。
    - 点缀元素：埃菲尔铁塔线描、法式栏杆花纹、邮票齿孔边、手写花体点缀。
    - 地图样式：暖色调复古地图。
    - 气质关键词：浪漫、慵懒、左岸文艺。
  - **其它城市（后续扩展）**：预留 theme 机制，如东京→都市霓虹/侘寂、京都→和风素雅等，届时各配一套。
- **落地方式**：以「城市主题 token（配色/字体/点缀/地图样式）」形式定义，可扩展到多城市，保证视觉一致。
- **约束**：主题只改「观感皮肤」，不改交互结构与信息架构；配色需保证可读性与明暗对比达标；mobile-first 下点缀不干扰内容。

---

## 5. 数据模型改造（对标 storymap builder，补字段）

三层模型骨架（POI / StoryStop / StoryLine / City）无需重构，主要是**补字段**与**拆分层加载索引**：

- **StoryLine 补**：主题标签[]、别名[]（供搜索）、关联名作/名人、海报、简介。
- **POI / StoryStop 补**：停留/步行提示（供自动播放算时长）、经典台词（浮卡用）、可选中译/原名、四类叙事已具备。
- **City 补**：主题 token（主色/辅色/字体气质/地图样式/点缀）。
- **新建搜索索引**：中英文名 + 别名 + 内容 token（去 pinyin）；`待收录` 标记。
- **新建轻/重索引拆分**：首页轻量核心索引 + 重字段延迟索引（支撑分层加载）。
- **共享 POI 跨故事线索引**：由 POI 被多故事线引用天然派生。

## 7. 验收标准

### 常规模式首页 Hub
- [ ] 首页含顶部常驻搜索框 + 全站统计条
- [ ] 世界地图为选城市主入口，巴黎可进入、其余城市「待解锁」占位
- [ ] 进入城市后提供视角：故事线卡片墙 / 城市地图分布 / 主题标签浏览，可切换
- [ ] 卡片墙/城市地图点/主题标签均可进入对应故事线页
- [ ] 轻量索引先加载、重字段空闲补载；地图进视口再初始化
- [ ] 支持 `?storyline=` / `?poi=` 深链定位

### 常规模式搜索
- [ ] 搜索覆盖 POI / 名人 / 名作三类
- [ ] 输入即出联想下拉，含类型 + 摘要 + 命中原因标签 + 关联内容 chip，支持 ↑↓/Enter/Esc 键盘导航
- [ ] 未收录内容打「待收录」徽标，点击给「敬请期待」不进空页
- [ ] 命中 POI → 进入常规模式展示该 POI 相关卡片/内容（锚定对应站）
- [ ] 命中名人/名作 → 进入常规模式展示相关 POI
- [ ] 无结果有空态兜底
- [ ] 搜索仅在已生成静态内容内匹配，无实时生成

### 常规模式故事线页（双栏联动）—— 核心
- [ ] 左站点时间轴 × 右路线地图双栏；桌面左右、移动端上下（地图顶部 sticky）
- [ ] 点站点↔点地图**双向**联动（高亮 + 定位 + 弹卡），点地图空白关闭浮卡
- [ ] 镜头用 panTo（仅超出视野才平移），不用 flyTo/setBounds，无眩晕
- [ ] 一键自动播放整条线：逐站推进 + 轨迹逐段生长 + 停留时长按站距动态计算 + 到末站自动停
- [ ] 已过/当前/未来段差异化着色
- [ ] POI 卡预留「其它故事线也讲到这里」跨线关联入口（首期占位）
- [ ] 地图提供矢量 + 影像双底图切换（不做地形/3D）
- [ ] 地点浮卡含 POI 名 + 四类叙事 + 图片（可放大）+ 拍照机位
- [ ] 键盘导航（←→/Home/End）+ aria-live 播报当前站
- [ ] `#stop=N` hash 记忆，刷新/分享可恢复
- [ ] reduced-motion 降级为跳转不动画；地图进视口才初始化
- [ ] 不新增独立 POI 页，POI 以锚点承载
- [ ] 全站不含昼夜切换

### 静态能力边界
- [ ] 首页/搜索/双栏联动/自动播放/底图/浮卡全部纯静态可用
- [ ] 追问卡/实时对话/实时生成明确划为后端钩子，本轮不做；未收录内容以「待收录」徽标承接

### 设计风格 / 视觉基调
- [ ] 统一「手账/明信片」底子（跨城一致）
- [ ] 每座城市一套主题 token（主色/辅色/字体气质/地图样式/点缀元素），机制为 `html[data-city]` + CSS 变量
- [ ] 巴黎主题体现浪漫气质：香槟金/玫瑰粉/塞纳灰蓝 + 铁塔线描/法式花纹/邮票齿孔等点缀
- [ ] 主题仅改观感、不改交互结构；配色保证可读性与明暗对比达标
