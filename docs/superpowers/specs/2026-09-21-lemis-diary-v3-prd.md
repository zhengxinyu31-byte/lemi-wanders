## 0. v2 为什么要改

用户实测 v2 demo 后给出两条判定:

| # | 问题 | 根因 |
|---|---|---|
| 1 | 游戏模式"未改造地图布局和风格" | 棋盘格子是画在真实 MapLibre 底图上的 Marker(`web/assets/game/ui.js:109-120`)。底图是等比例真实巴黎,格子只是浮在上面的小圆点——**它不是棋盘,是加了标记的地图**。大富翁的"盘面感"完全没有,城市风格为零 |
| 2 | 常规模式缺完整链路设计 | v2 的图鉴模式只有 60 行 `codex.js` + Scrollama 滚动,没有交互事件表、没有状态机、没有导航控件。是"能跑",不是"设计过" |

**本次改动的性质**:游戏模式把 MapLibre **整个拿掉**,改为纯 SVG/DOM 风格化棋盘;常规模式**才**使用真实地图,并按 storymap 的完整链路重做。两个模式从"共用一张地图、换皮"变成"两套截然不同的表现层、共用一份数据"。

## 1. 产品定位与双模式分工

> 一款"用大富翁玩法逛世界文化地标"的收集游戏,退出游戏还能当认真的文化地图查。

| | 游戏模式(默认) | 常规模式 |
|---|---|---|
| 面向 | 想玩的人 | 想查资料的人 |
| 空间表达 | **风格化棋盘**(SVG,无真实地图) | **真实地图**(MapLibre) |
| 主要动作 | 摇骰子、走格、掉卡、集卡 | 逐站浏览、看五段式内容、自动播放 |
| 导航方式 | 骰子决定(不可自由跳站) | 完全自由(点击/键盘/自动播放/深链) |
| 进度 | 有(localStorage) | **无**(纯只读) |
| 主线 | 一条故事线 = 一个棋盘 | 一条故事线 = 一条时间轴 |

两模式**状态解耦**:常规模式除 `lemi_lang` 外不读写 localStorage。这条是 v2 已确立的规则,继续执行。

## 2. 游戏模式:塞纳河缎带棋盘

### 2.1 为什么是这个形状

7 个 POI 的真实坐标算出来是这样的:

| # | POI | lat | lng | 相对塞纳河 |
|---|---|---|---|---|
| 1 | place-estrapade(Emily 公寓) | 48.8453 | 2.3448 | 左岸 |
| 2 | pantheon(先贤祠) | 48.8470 | 2.3438 | 左岸 |
| 3 | cafe-de-flore(花神咖啡馆) | 48.8541 | 2.3326 | 左岸 |
| 4 | jardin-palais-royal(皇家宫殿花园) | 48.8649 | 2.3378 | 右岸 |
| 5 | palais-garnier(加尼叶歌剧院) | 48.8714 | 2.3320 | 右岸 |
| 6 | pont-alexandre-iii(亚历山大三世桥) | 48.8635 | 2.3135 | **河上** |
| 7 | tour-eiffel(埃菲尔铁塔) | 48.8561 | 2.2895 | 左岸 |

即:**左岸 1-2-3 → 跨河 → 右岸 4-5-6 → 跨回左岸 7**,且第 6 站本身就是一座桥。

这个"两次过河"的叙事弧不是设计出来的,是数据里本来就有的。缎带棋盘把它显式化:塞纳河是一条横贯棋盘的蓝色和纸胶带,格子沿两岸铺开,过河处画桥。**过河 = 章节转折**,棋盘形状本身在讲故事。

### 2.2 棋盘几何(规范)

棋盘定义在**归一化坐标空间** `x ∈ [0,1]`, `y ∈ [0,1]`(y=0 为上边即右岸侧,y=1 为下边即左岸侧),由构建管线计算、前端按容器尺寸缩放渲染。真实经纬度**不参与游戏模式渲染**(但仍保留在数据里供常规模式与 POI 关联使用)。

**塞纳河中心线**:

```
y_river(x) = 0.50 + 0.06 · sin(2π · x)
```

河带半高 `0.085`(即河带上缘 `y_river - 0.085`,下缘 `y_river + 0.085`)。

**格子位置**:

```
x_i = 0.05 + 0.90 · (i / 19)                      i = 0..19,均匀分布
y_i = y_river(x_i) + b_i · 0.26 + jitter_i
jitter_i = 0.035 · (i 偶数 ? +1 : −1) · b_i       仅当 |b_i| = 1 时生效,否则为 0
```

`b = +1` 左岸车道(下),`b = -1` 右岸车道(上),`b = 0` 河心。车道跟着河的曲线走,所以整体是有机的缎带感而非死板直线。

`jitter` 让同岸连续格子上下交错,避免排成一条直线 —— 既是手账拼贴该有的随意感,也拉开了相邻格的中心距。

### 2.2.1 几何验证(参数已实测,不得随意改动)

上述所有常数(`0.26` 车道偏移、`0.05` 边距、`0.035` jitter、`b16..b18` 的 `0.62/0.78/0.82`)都是解算出来的,不是估的。在 **960×600** 画布下:

| 指标 | 实测值 | 判据 |
|---|---|---|
| 最小相邻中心距 | **47.6px**(格 17→18) | 需 > 40px |
| 次小中心距 | 48.4px(格 18→19) | — |
| **最小相邻边缘间隙** | **11.5px**(格 4→5,photo→poi) | 需 > 6px(否则视觉粘连) |
| 误压入河带的岸上格 | **0** | 必须为 0 |
| `by` 取值范围 | 0.147 .. 0.855 | 必须在 [0.03, 0.97] 内 |

格子尺寸:**POI 格 40×48px,路途格/彩蛋格 28×28px**。全部 19 对相邻格均由横向间距 `dx = 45.5px` 保证分离,最紧一对(格 4→5)边缘仍留 11.5px。POI 格之间永不相邻(每段至少 1 个路途格),所以不存在 40px 对 40px 的挤压。

**实现时必须有一个测试断言上表五项指标**。调参过程中曾出现两处真实缺陷:早期 `lane_offset=0.22` 让第 16 格落在河带里(一个本该"下桥回左岸"的格子泡在水上),`b18=0.85` 时 jitter 恰好抵消 y 差使格 18→19 的中心距掉到 45.5px。这类错误肉眼看公式看不出来,只有算出来才知道 —— 所以尺寸一旦调整(比如把路途格从 28px 改大),**必须重跑该测试**,不能只改数字。

### 2.3 方位取舍(明写)

路线按**从左到右**阅读。真实地理上这趟旅程是**由东向西**(公寓 lng 2.3448 → 铁塔 lng 2.2895),所以棋盘在东西轴上做了**镜像**。

- **保留**:左岸/右岸的真实归属、两次过河的真实顺序、桥在河上
- **放弃**:罗盘方位。因此棋盘**不画指北针、不标经纬度**,不声称自己是定向地图

这是刻意的:用户明确说"无需等比例地图",而阅读顺序(左→右)带来的顺畅感,比一个没人会去核对的罗盘方位更值钱。**常规模式用真实地图,方位在那里是准的。**

### 2.4 白天 / 夜晚

`night_from_index = 15`,即**棋子首次抵达或越过第 15 格(亚历山大三世桥)时切夜景**,一次性、不可逆,500ms 交叉淡入。

改自 v2 的 13。理由:第 15 格就是桥,而数据里桥的描述是"日落时分金色雕塑最美",铁塔是"夜间整点有 5 分钟闪灯秀"。落在桥上的那一刻天黑,**日落与一张 POI 卡的掉落同时发生**,比落在一个无名路途格上更有记忆点。白天 15 格 / 夜晚 5 格。

夜景表现(**纯 CSS,无需换底图** —— 这是去掉 MapLibre 的直接收益):

| 元素 | 白天 | 夜晚 |
|---|---|---|
| 纸底 | `#f4ece0` 牛皮纸 | `#2a2f3d` 深蓝墨 |
| 塞纳河胶带 | `#7fb2cc` | `#3d5a7a` + 微弱波光 |
| 格子描边 | `#8a7a68` | `#6b7590` |
| 铁塔格(19) | 常态 | **金色发光**(`box-shadow` 脉冲,2s 循环) |
| 整体 | — | `filter: brightness(0.92)` |

### 2.5 手账拼贴视觉风格

选定风格:**手账拼贴(scrapbook)**。理由:与 "Lemi's **Diary**" 这个名字、与拍立得卡片体系是同一套视觉语言,自洽度高于其他候选。

**约束**:没有插画师。所有视觉由 CSS + 内联 SVG 手写实现,照片一律用已有的维基真实图片。**不得引入任何需要外部图片资源的装饰**。

设计 token(定义在 `base.css`):

```css
--paper:        #f4ece0;   /* 牛皮纸底 */
--paper-edge:   #e0d3c0;   /* 纸张阴影 */
--ink:          #3a3228;   /* 手账墨色(正文) */
--ink-soft:     #8a7a68;   /* 淡墨(描边/次要) */
--seine:        #7fb2cc;   /* 塞纳河和纸胶带 */
--tape:         #e8d9a8;   /* 米黄胶带 */
--stamp-r:      #fdfaf3;   /* R 卡:米白哑光 */
--stamp-sr:     #d4af37;   /* SR 卡:金 */
--left-bank:    #e8ead9;   /* 左岸纸片(淡橄榄) */
--right-bank:   #f0e3dd;   /* 右岸纸片(淡陶土) */
```

具体做法:

| 元素 | 实现 |
|---|---|
| 纸纹 | SVG `feTurbulence` 生成一次性噪点,`opacity: 0.05` 叠在纸底上(已实测:颗粒质感可见) |
| 塞纳河 | 沿 `y_river(x)` 的 SVG `path`,`stroke-width` 对应河带高,`opacity: 0.55`(已实测:弯曲缎带感成立) |
| 两岸 | 两块极淡的不规则纸片(SVG path,边缘故意不直),压在河带下层 |
| 路途格 | **2px 虚线描边方块**,28×28px,`border: 2px dashed var(--ink-soft)` |
| POI 格 | 拍立得小白框(下边留白更宽),内嵌 POI 缩略图,40×48px + 轻投影 |
| 彩蛋格 | 金色蜡封圆章(`radial-gradient` 偏心高光 + 内阴影),直径 28px,带 `★` |
| 路线 | 格子之间的虚线,`stroke-dasharray: 3 4`,走过的段变实线 |
| 四角 | washi tape 贴片(旋转 −4°/+3° 的半透明色块) |
| 站名标注 | **常规字体**(思源黑体)。手写体只在卡片末尾的引语处使用——用户已明确"手写体不易辨认" |

**路途格为什么不用邮票齿孔(实测结论,不要再试)**:原方案是 `radial-gradient` + `mask-composite` 抠出齿孔。实测在 26-32px 的实际尺寸下,**齿孔完全看不出来**,与普通方框无异(放大 3 倍才可辨);"每边 3 个小齿"的加强版同样无效。另一个候选"撕齿小票"(`mask` 的 `padding-box`/`border-box` 组合)有**真实渲染缺陷** —— 上边与左边整段缺失。虚线描边在小尺寸下识别度最高,且"剪贴虚线"本身就是手账语汇。

验证页保留在 `/tmp/lemi-viz/`(probe.html 全景、stamp.html 六方案对比),后续调风格可复用。

**Lemi 棋子**:戴牛仔帽、挎相机的小仓鼠。当前实现是 `🐹` emoji(占位)。本期改为**内联 SVG 简化剪影**(圆身 + 牛仔帽轮廓 + 相机方块 + 背包),约 30 行 path。走路时用 CSS `transform` 平移,**不加身体起伏等附加动作**(用户已明确删除)。

### 2.6 视口与相机(取代 MapLibre 运镜)

棋盘是固定长宽比 `16:10` 的 SVG。相机 = 棋盘图层上的一个 CSS `transform: translate() scale()`。

| 场景 | 行为 |
|---|---|
| 桌面(≥1024px) | 整盘可见,`scale` 按容器宽度自适应,相机**从不移动** |
| 移动端(<1024px) | `scale = 1.8`,相机跟随 Lemi,**但只在 Lemi 接近视口边缘 15% 时才平移一次**,`duration: 600ms` |
| 落 POI 格 | 该格**局部放大脉冲**(`scale(1.12)` → 回弹,350ms),取代 v2 的 `flyTo` 俯冲 |
| `prefers-reduced-motion` | 相机平移改为瞬时,格子脉冲取消 |

"只在接近边缘才平移"这条规则直接复用 v2 已测试的 `mapkit.needsPan(point, viewport, 0.15)` —— 它计算的是像素与视口的关系,和底层是地图还是 SVG 无关。**这个函数和它的测试在本次改动中原样保留。**

### 2.7 一回合节拍

| 环节 | 时长 | 细节 |
|---|---|---|
| 按下骰子 | 100ms | 下沉 2px |
| 骰子翻滚 | 400ms | 3D 翻滚,末段减速 |
| 背包步行 | ≤1000ms | 逐格平移,格子多则每格走得快;无附加小动作 |
| 掉卡 | 600ms | 出片 150 + 显影 350 + 定影 100 |
| 其他格 | 3000ms | 机会/机位/街头统一 3 秒 |

全程约 2.1 秒。这套数值 v2 已定稿并落地为 CSS token(`--t-press` … `--t-info`),**本次不变**。

### 2.8 已删除项(沿用 v2 决议)

全部音效、落地震动、步行起伏/帽子/相机小动作、卡片飞入卡册动效、四段光照渐变。原则:动效只保留关键节点。

## 3. 常规模式:真实地图 + 故事线时间轴

### 3.1 关键设计修正:不用滚动驱动

storymap 拆解得出一个反直觉的事实:**它不是 scrollytelling**。它的 `IntersectionObserver` 只用于地图懒加载(`profile-app.js:4764`),章节切换靠**点击时间线节点 / 键盘 ←→ / 自动播放**(`4266-4373`)。

v2 用 Scrollama 做滚动驱动,方向是错的。对"想查资料的人"来说,**显式导航优于线性滚动**:能直接跳到想看的那站,而不是被迫从头滚。

因此常规模式改为 storymap 式的**显式导航**,并因此获得三个额外收益:

- 不再受 Scrollama 的 `vh` 单位禁令约束
- 不再受"不能置于 iframe"约束
- 移动端不再有"滚动改变 vh → 重触发 resize"的隐患

`Scrollama` 依赖整个移除。

### 3.2 布局

```
桌面(≥1024px)                          移动(<1024px)
┌──────────┬─────────────────┐          ┌─────────────────┐
│ 时间轴    │                 │          │   地图 40% sticky│
│ 7 站      │   真实地图       │          ├─────────────────┤
│ (可点)    │   MapLibre      │          │ 站点内容(纵向滚)│
│          │                 │          │ 时间轴收为顶部   │
│ 当前站    │                 │          │ 横向胶囊条       │
│ 五段式内容│                 │          │                 │
└──────────┴─────────────────┘          └─────────────────┘
  34%           66%
```

### 3.3 内容呈现

每站展示该 POI 的五段式内容(沿用 v1 数据结构,`narrative[]`):

| type | 标签 | 说明 |
|---|---|---|
| `scene` | 🎬 剧中场景 | 该地点在《艾米莉在巴黎》中的戏份 |
| `anecdote` | 💬 趣闻 | 现实中的轶事、争议 |
| `masterpiece` | 📖 名作 | 与此地相关的文学/艺术作品 |
| `history` | 🏛 历史 | 建筑/地名的来历 |
| `practical` | 🧭 实用 | 开放时间、交通、拍照提示(来自 POI 的 `practical` 字段) |

不是每站都有全部 5 段(数据实际是 3-4 段)。**缺失的段不渲染空标题。**

### 3.4 运镜策略

参数以 storymap 实测值为起点(`/tmp/storymap-teardown.md` §6.2):

| 场景 | 动作 | 参数 |
|---|---|---|
| 进入页面带 `#stop=N` | `flyTo` | `duration:700, curve:1.4, speed:1.2, essential:true, zoom:15, pitch:0` |
| 进入页面无 hash | `fitBounds` 全景 | 7 站外接框 + `padding:60`,`duration:0` |
| 点时间线节点(相邻站) | `flyTo` | 同上,`duration:700` |
| 点时间线节点(跨站跳转) | `flyTo` | `duration:900`(距离远,给足时间) |
| 点地图 marker | `flyTo` + 脉冲 | 同上 + marker `pulse` 650ms |
| 点「全景」按钮 | `fitBounds` | `duration:420` |
| 自动播放逐站前进 | `flyTo` | `duration:1150`,**站间停留** `clamp(dist_km × 600, 1800, 3600) ms` |
| `prefers-reduced-motion` | `jumpTo` | 瞬时,但 `essential:true` 仍必须带 |

**`essential: true` 是硬要求**:不带它,系统级"减弱动态效果"会把 `flyTo` 静默降级成 `jumpTo`,运镜彻底消失。

**轨迹线**:7 站按顺序连成一条线。本期做**简化版**——直线段 + `line-dasharray`,不做 storymap 的 Catmull-Rom 曲线平滑(收益小、复杂度高)。已走过的段用实线,未到的用虚线。方向箭头放在每段中点。

### 3.5 标记点状态

| 状态 | 表现 |
|---|---|
| `is-past` | 小圆点,`--ink-soft`,半径 6 |
| `is-active` | 大头针图标,`--seine`,半径 9,zIndex 高 |
| `is-future` | 小圆点,描边虚线,半径 6 |
| 日/夜分段 | 第 6、7 站(桥、铁塔)带 🌙 角标,与游戏模式的 `night_from_index` 判定同源 |

夜晚判定必须用 **board index** 与 `night_from_index` 比,不能用 `stop.order`(1..7)—— 这两个是不同单位系统,v2 曾因此让全部 7 章都判成白天。该修复已在 `codex.js:15-20` 的 `poiBoardIndex()` 中落地,**本次保留**。

### 3.6 「第三维」= 故事线切换 + 自动播放

storymap 的三维是 [空间轨迹] × [时间章节] × [可对话人格]。我们**不做对话**(纯静态站无后端,且编造式问答会踩内容真实性红线),第三维改为:

- **故事线切换**:顶部胶囊条。本期巴黎 3 条线,仅《艾米莉在巴黎》可用,另 2 条显示"规划中"且不可点。这是明写的下一步钩子
- **自动播放**:一键从第 1 站巡演到第 7 站。这是纯静态站能做到、且观感最好的第三维。站间停留按真实地理距离动态计算(远则慢),复用 storymap 的思路

## 5. 状态机

### 5.1 游戏模式状态

| 状态 | 读者 | 写者 | 持久化 |
|---|---|---|---|
| `position` | 棋子位置、相机、骰子上限 | `roll()` | ✅ localStorage |
| `night` | 棋盘主题类、铁塔发光 | 越过 idx 15 时一次性 | ✅ |
| `cards[]` | 卡册、重复判定 | 收卡 | ✅ |
| `ssr_shards` | 卡册 SSR 位 | 完成故事线 | ✅ |
| `rolling` | 骰子禁用 | 点骰子 / 事件播完 | ❌ 内存 |
| `openCard` | 阻塞骰子 | 掉卡 / 收卡 | ❌ 内存 |
| `visited{}` | 格子已走视觉、路线实线化 | 每次经过 | 由 `position` 派生 |

```
position: N ─摇骰(1-6)→ min(N+roll, 19),逐格触发事件
night:    false ─首次 position≥15→ true  (单向,不可逆)
turn:     idle ─点骰子→ rolling ─翻滚完→ playing ─事件播完→ idle
                                          └─遇卡片→ awaitCollect ─收卡→ playing
```

### 5.2 常规模式状态

| 状态 | 读者 | 写者 | 持久化 |
|---|---|---|---|
| `activeStop` | 时间线高亮、地图运镜、内容区滚动 | 点击/键盘/自动播放/hash | URL hash(`replaceState`) |
| `playing` | 播放按钮图标、站间 timer | 播放按钮/任何手动操作 | ❌ |
| `mapReady` | 运镜是否可执行 | 地图 `load` 事件 | ❌ |
| `lang` | 全部文案 | 语言切换 | ✅ `lemi_lang`(**唯一**跨模式共享项) |
| `storylineId` | 时间轴、地图数据 | 故事线胶囊 | ❌ 本期固定 |

```
mapReady: false ─map.load→ true ─SDK失败→ degraded(静态可读)
activeStop: null(全景) ⇄ 1..7  ─replaceState 同步 #stop=N
playing: false ─点播放→ true ─到末站/手动操作/点暂停→ false
```

**两模式状态互不可见**:`codex.js` 中不得出现 `lemi_state` / `hasCard` / `cardCount` / `addCard`。v2 已有一条 grep 测试守着这条规则,**保留**。

2. **游戏模式棋盘**:SVG 渲染 + 手账风格 + 相机 + 日夜主题(用户最不满的部分,优先)
3. **游戏模式联调**:接回已保留的骰子/掉卡/卡册逻辑
4. **常规模式**:显式导航状态机 + 真实地图 + 时间轴 + 自动播放
5. **模式互切 + 移动端 + 无障碍**
6. **内容审计**(独立后置步骤,沿用 v2 决议:交叉验证 + 对抗性审查,不要求学术级考据)

## 13. 已知取舍

| 取舍 | 代价 | 换来 |
|---|---|---|
| 游戏模式弃用真实地图 | 失去"真实街道"的可信感 | 真正的棋盘感 + 城市风格 + 夜景纯 CSS 可做 |
| 棋盘东西轴镜像 | 罗盘方位不准(故不画指北针) | 路线顺着阅读方向(左→右) |
| 常规模式弃用 scrollytelling | 少了滚动沉浸感 | 可自由跳站(查资料者的真实需求)+ 移除 3 条 CSS 约束 |
| 不做可对话人格 | 少一个维度 | 不破纯静态约束、不引入编造风险 |
| 轨迹线用直线不用曲线 | 观感略生硬 | 省掉 Catmull-Rom + 逐帧生长的复杂度 |
| 首期 1 条故事线 | SSR 拿不到 | 先验证玩法 |
| Lemi 用 SVG 剪影而非插画 | 形象精细度有限 | 无需插画师,零外部资源 |

## 14. 验收标准

游戏模式:

- [ ] 页面**不加载 MapLibre**(grep `board.html` 无 maplibre)
- [ ] 棋盘可见 20 格,格子类型视觉可区分,塞纳河横贯,两岸底色不同,第 15 格压在河上
- [ ] **几何测试**断言:最小相邻中心距 > 40px、岸上格误压河带数 = 0、`by` 全部落在 [0.03, 0.97]、`banks` 长度 = 格数
- [ ] Lemi 是 SVG 而非 emoji,落在第 0 格
- [ ] 开局自动掉第 0 格的卡;摇 6-7 次骰走完 20 格;卡册达 **10/10**;跳过格数 **0**
- [ ] 越过第 15 格切夜景,铁塔格发光,不可逆
- [ ] 卡片可**鼠标点任意位置**和**键盘 Enter/Space** 两种方式收取
- [ ] 卡册 10 位,未获得为剪影 + `?`,SSR 显示 `n/3`
- [ ] localStorage 禁用时仍可完整玩一局

常规模式:

- [ ] **不加载 Scrollama**
- [ ] 7 站时间线可点,marker 可点,键盘 ←→/Home/End 可用
- [ ] `#stop=N` 深链进入直接定位;切站 `replaceState` 同步
- [ ] 自动播放从第 1 站走到第 7 站后自动停;巡演中任何手动操作先停播放
- [ ] 全部 `flyTo` 带 `essential: true`
- [ ] 第 6、7 站带夜晚角标(用 board index 判定,非 stop.order)
- [ ] 全程不写 localStorage(除 `lemi_lang`);grep 无 `lemi_state`/`hasCard`/`cardCount`/`addCard`

内容:

- [ ] 三个无合格引语的 POI 卡片不渲染手写体栏
- [ ] 莫泊桑铁塔餐厅杜撰句在全仓库与 dist 中均不存在(含回归测试)
