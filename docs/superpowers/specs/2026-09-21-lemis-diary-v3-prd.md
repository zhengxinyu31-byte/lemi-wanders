## 1. 产品定位与三条主链路

> 一款"用大富翁玩法逛世界文化地标"的收集游戏;退出游戏能当认真的文化地图查;还能反查任一名人/角色/作品在城市里走过的动线。

三条主链路共享**同一份数据**(POI + 故事线 + 实体图谱),各自有独立表现层:

| 主链路 | 入口 | 空间表达 | 核心动作 | 进度 |
|---|---|---|---|---|
| **A 游戏模式**(默认) | 首页「🎲」 | 风格化 SVG 棋盘 | 摇骰、走格、集卡、遇见人物 | 有(localStorage) |
| **B 常规模式** | 「📖」/ 卡片深链 | 真实地图 MapLibre | 逐站看五段式内容、自动播放 | 无(纯只读) |
| **C 搜索动线** | 全局搜索框 | 真实地图 MapLibre | 搜实体 → 看其 POI 动线 | 无(纯只读) |

B 与 C **共用同一张真实地图与运镜内核**(storymap 的 `locations[]` + `activeIndex` + `flyTo`),区别只在数据源:B 喂"故事线",C 喂"实体动线"。A 独立。

三链路互相跳转,状态解耦:除 `lemi_lang` 外,B/C 不读写游戏进度 localStorage。

### 1.1 空间层级

```
世界地图(城市选择)                         ← 后期,本期占位
  └── 巴黎 · 3 条故事线 · 实体图谱            ← 本期
        ├──《艾米莉在巴黎》棋盘(12 格)        ← 游戏模式:可玩
        ├── 另 2 条故事线                     ← 占位"规划中"
        └── 25 人 / 9 作品 / 36 关系          ← 搜索动线数据源
```

## 2. 数据模型

### 2.1 沿用不变

`POI` / `StoryStop` / `StoryLine` / `City` / `Card` / `Quote` / `StreetCard` 沿用 v2。内容真实性 gate 沿用(`Quote` 需 `verified=True` + 非空 `source`/`source_url`;`StreetCard` 需 `verified=True` + ≥2 独立来源)。

### 2.2 `StoryStop` 扩展:place_role

```python
place_role: str   # fictional_setting | real_footprint | commemoration
```

- `fictional_setting`:剧/作品的虚构取景(如 Emily 家的绿门)
- `real_footprint`:真实人物在此活动过(如萨特在花神)
- `commemoration`:纪念性关联(如傅科摆在先贤祠)

用途:仅作卡片故事线面上的**一个标签徽章**,以及搜索动线区分虚构/真实点。**不再决定卡片正反面**(翻面已取消)。

### 2.3 新增 Person / Work / Relation

```python
@dataclass
class Person:
    id: str; name_zh: str; name_en: str; name_original: str = ""
    aliases: List[str]; birth_year: Optional[int]; death_year: Optional[int]
    role: str                    # 哲学家/作家/画家/工程师...
    is_fictional: bool = False   # Emily/Gabriel/Mindy = true
    silhouette_id: str = ""      # 「遇见的人」剪影素材(SVG)
    sources: List[str]; verified: bool = False

@dataclass
class Work:
    id: str; title_zh: str; title_original: str; year: Optional[int]
    type: str                    # novel|philosophy|painting|building|tv_series
    author_person_id: str
    sources: List[str]; verified: bool = False

@dataclass
class Relation:
    subject_type: str            # person|work
    subject_id: str
    predicate: str               # frequented|lived_at|buried_at|designed|
                                 # authored|set_in|protested_against|partner|
                                 # contemporary|co_signatory|commemorated_at...
    object_type: str             # place|person|work
    object_id: str
    note: str                    # 措辞依据(收紧后的准确表述)
    sources: List[str]; verified: bool = False
```

**构建时 gate**(复用 `verify.py` 模式):`verified != True` 或 `len(sources) < 2` 的 Person/Work/Relation **不输出到前端**。`sources` 本身不下发(验证过即可)。

## 3. 游戏模式(A):塞纳河缎带棋盘

### 3.1 棋盘形状的由来

7 个 POI 真实坐标呈现:**左岸 1-2-3 → 跨河 → 右岸 4-5 → 河上桥 → 折回左岸 7**,两次过河。缎带棋盘把它显式化:塞纳河是一条横贯棋盘的蓝色和纸胶带,格子沿两岸铺开,过河处画桥。**过河 = 章节转折**。

### 3.2 棋盘几何(规范 + 《艾米莉》线实例)

归一化坐标 `x,y ∈ [0,1]`(y=0 上=右岸侧,y=1 下=左岸侧)。真实经纬度**不参与游戏渲染**。

```
塞纳河中心线:  y_river(x) = 0.50 + 0.06·sin(2π·x)     河带半高 0.085
格子 x 坐标:    x_i = 0.05 + 0.90·(i / (N−1))          N = 该线总格数
格子 y 坐标:    y_i = y_river(x_i) + bank_i·0.26 + jitter_i
jitter_i = 0.035·(i 偶?+1:−1)·bank_i                   仅当 |bank_i| = 1
```

`bank=+1` 左岸(下)、`−1` 右岸(上)、`0` 河心、中间值(如 0.7)为下桥过渡。

**每故事线格数规则**:`N = POI 数 + 填充格`,夹在 **5-15**。填充格 = 3 个彩蛋格(供 3 张 SR,必备)+ 若干路途格(street/chance,按 POI 间真实距离用最大余额法分配),使 N ≤ 15。

**《艾米莉在巴黎》线实例(N=12)**:

| idx | 类型 | 内容 | bank | bx | by | 说明 |
|---|---|---|---|---|---|---|
| 0 | poi | place-estrapade | +1.0 | 0.050 | 0.814 | 左岸·起点 |
| 1 | street | paris-bonjour | +1.0 | 0.132 | 0.769 | 左岸 |
| 2 | poi | pantheon | +1.0 | 0.214 | 0.853 | 左岸 |
| 3 | easter | paris-sr-petition | +1.0 | 0.295 | 0.783 | 左岸·SR |
| 4 | poi | cafe-de-flore | +1.0 | 0.377 | 0.837 | 左岸 |
| 5 | chance | paris-metro-doors | 0.0 | 0.459 | 0.515 | **过河桥上** |
| 6 | poi | jardin-palais-royal | −1.0 | 0.541 | 0.190 | 右岸 |
| 7 | easter | paris-sr-existentialism | −1.0 | 0.623 | 0.233 | 右岸·SR |
| 8 | poi | palais-garnier | −1.0 | 0.705 | 0.148 | 右岸 |
| 9 | poi | **pont-alexandre-iii** | 0.0 | 0.786 | 0.442 | **河心·日落·夜切** |
| 10 | easter | paris-sr-tourist-gaze | +0.7 | 0.868 | 0.638 | 下桥回左岸·SR |

7 POI(0,2,4,6,8,9,11)+ 3 easter(3,7,10)+ 2 路途(1 street,5 chance)= 12 格。两次过河:tile 4→6 经 tile 5(桥),tile 8→11 经 tile 9(河上桥)。所有 `by ∈ [0.148, 0.853]`,岸上格无一压入河带,河心格(5,9)刻意在河上。

### 3.3 方位取舍

路线**从左到右**阅读;真实地理是由东向西,故棋盘在东西轴**镜像**。保留左/右岸真实归属、两次过河真实顺序、桥在河上;放弃罗盘方位(不画指北针、不标经纬度)。方位准确性交给常规模式的真实地图。

### 3.4 白天 / 夜晚

`night_from_index = 9`(《艾米莉》线):棋子首次抵达/越过第 9 格(亚历山大三世桥)切夜景,一次性、不可逆,500ms 交叉淡入。白天 9 格 / 夜晚 3 格。落在桥上那一刻天黑,与日落 + 一张 POI 卡掉落同时发生。

夜景纯 CSS(去掉 MapLibre 的直接收益):纸底转深蓝墨、河胶带转深色微波光、铁塔格(11)金色脉冲发光、整体 `brightness(0.92)`。

### 3.5 手账拼贴视觉

CSS + 内联 SVG 手写实现,照片用已有维基真实图,**不引入任何外部图片资源**。纸纹(`feTurbulence` opacity 0.05)、塞纳河(沿 `y_river` 的 SVG path)、两岸(极淡不规则纸片)、路途格(2px 虚线描边方块 28×28px)、POI 格(拍立得小白框 40×48px + 缩略图)、彩蛋格(金色蜡封圆章 ★ 28px)、路线(格间虚线,走过转实线)、四角 washi tape。站名用常规字体(思源黑体),手写体仅用于卡片引语。

**Lemi 棋子**:戴牛仔帽挎相机的小仓鼠,内联 SVG 剪影(约 30 行 path)。走路时 CSS `transform` 平移,无身体起伏等附加动作。

### 3.6 一回合节拍

| 环节 | 时长 | 细节 |
|---|---|---|
| 按骰子 | 100ms | 下沉 2px |
| 骰子翻滚 | 400ms | 3D 翻滚末段减速 |
| 逐格步行 | ≤1000ms | 逐格平移,格多则每格快 |
| 掉卡(POI/彩蛋) | 600ms | 出片 150 + 显影 350 + 定影 100 |
| 其他格(街头/机会) | 3000ms | 统一 3 秒 |

已删除项:全部音效、落地震动、步行附加小动作、卡片飞入卡册动效、四段光照渐变。动效只保留关键节点。

## 4. 卡片系统:单面 + 故事线切换(取消翻面)

### 4.1 结构:一个地理底座 + 可切换的故事线面

取消"正面虚构层 / 翻转背面真实层"。每张卡是**一张不翻转的拍立得**,由两层叠成:

```
┌─────────────────────────┐
│  [POI 拍立得照片]         │  ← 地理底座(所有卡共享,永远显示)
│                          │
│  先贤祠 Panthéon         │  ← POI 名
│  📍 5 Pl. du Panthéon    │
│  🏛 1790 落成 · 新古典    │  ← 现实简介:地址/建成年代/风格
│  🕐 10:00–18:30          │  ← 开放信息
│  📷 从 Rue Soufflot 正对  │  ← 机位提示(原 photo 格并入这里)
│ ┌─────────────────────┐  │
│ │《艾米莉在巴黎》▾      │  │  ← 故事线切换器(仅当卡属多条线时出现)
│ │ 🎬 剧中:Emily 曾…    │  │  ← 故事线面:场景/轶事/名作/历史
│ │ [real_footprint 徽章]│  │  ← place_role 作为标签,不再决定正反
│ └─────────────────────┘  │
└─────────────────────────┘
```

- **地理底座**:POI 拍立得照片 + POI 本身的现实简介(名称/地址/建成年代/风格/开放时间/机位)。**所有卡统一,恒显**。
- **故事线面**:该 POI 在**当前进行中的故事线**里的叙事内容(五段式的 scene/anecdote/masterpiece/history 摘要)。默认显示当前故事线的那一面。
- **`place_role` 徽章**:在故事线面角落显示一个小标签(🎭虚构取景 / 👣真实足迹 / 🕯纪念),不再控制翻转。

### 4.2 故事线切换器

- **触发条件**:仅当该 POI 同时属于 ≥2 条故事线时,故事线面顶部出现切换器(下拉 / 左右翻页箭头)。只属 1 条线则不显示切换器,直接展示那条线。
- **默认选中**:用户当前所在故事线(游戏模式 = 正在玩的棋盘对应线;常规模式 = 当前时间轴对应线)。
- **切换行为**:平移切换故事线面内容(**无 3D 翻转**),地理底座不动。
- **本期实况**:首期仅《艾米莉在巴黎》1 条线,故切换器**本期不出现**;但数据结构与 UI 预留,第 2 条线上线即生效。这是明写的下一步钩子。

### 4.3 卡片获取与卡册(沿用 v2 卡池)

| 卡 | 获取 | 《艾米莉》线 |
|---|---|---|
| R | POI 格必掉 | 7 张 |
| SR | 彩蛋格 | 3 张 |
| SSR 碎片 | 跑完 1 条故事线 | 1 枚(共需 3) |
| SSR | 集齐 3 枚合成 | 本期锁定,显示 `n/3` |

卡册分母 **10**(7R+3SR),SSR 不计入。街头/机会格内容**不进卡册**。未获得卡显示**剪影 + `?`**。收卡:点卡片任意位置 / 键盘 Enter·Space → 收入卡册 → toast「已收入卡册」。重复获得同卡:仍展示卡面,不重复计数、不发 toast。

**SSR 分享钩子(优先级最低,末期做)**:获得 SSR 卡时提示分享,分享图带本站二维码(固定 URL 静态 PNG,零运行时依赖)。

## 5. 「遇见的人」:每格候补一个剪影

### 5.1 机制

保留这一栏,但**不展示总数**(不出现 "3/12 已解识" 之类进度条),避免变成又一个集卡焦虑源。

- **候补规则**:棋子每到一格,若该格 `person_id` 非空且该人物**尚未解识**,则在「遇见的人」栏**候补一个人物剪影**(灰色 SVG 轮廓 + `?`)。
- **一次一个**:同一时刻栏内**最多一个待解识剪影**;点亮(解识)后,下一格才可能再候补下一个。若到达的格已候补过或人物已解识,不重复候补。
- **不承诺总量**:用户永远不知道"一共有多少人""还差几个"——是探索惊喜,非清单任务(Zeigarnik 开放回路,单个即可,不堆积)。

### 5.2 解识交互

| 触发 | 响应 |
|---|---|
| 栏内出现待解识剪影 | 剪影轻微呼吸动效,提示可点 |
| 点击剪影 | 展开人物小卡:姓名 + 生卒 + role + 一句"ta 与此地的关系"(取自 Relation 的 note)+ `is_fictional` 时标"🎭 剧中角色" |
| 关闭人物小卡 | 剪影变为已点亮(彩色),栏内候补位空出 |
| 点已点亮的人物 | 重新展开其小卡(只读) |
| 人物有可查动线 | 小卡底部「查看 ta 的动线 →」跳转搜索动线(链路 C),预填该人物 |

### 5.3 数据来源

候补谁由 `BoardTile.person_id` 决定,该字段构建时从 **person↔place 关系**(21 条)择一填入(优先 `real_footprint` 类,如先贤祠格候补雨果/伏尔泰、花神格候补萨特)。虚构角色(Emily)可挂在其取景 POI 格(绿门 → Emily)。同一 POI 关联多人时,构建时只取一个填入该格(其余人物仍可经搜索动线 C 触达)。

## 6. 搜索动线(C):人物/角色/作品 → POI 动线

### 6.1 定位

把已验证的**实体图谱**变成可查询入口:搜任一名人、虚构角色或作品,在**真实地图**上高亮出 ta / 它关联的 POI 序列,连成一条动线。这是 B 常规模式的"故事线"之外的**第二种地图数据源**,复用同一套地图与运镜内核。

### 6.2 入口与搜索

- **全局搜索框**:游戏模式顶栏 + 常规模式顶栏均可唤起(图标 🔍)。
- **可搜对象**:Person(真实 + 虚构)、Work。**支持中/英/原名 + aliases 模糊匹配**(如 "雨果"/"Hugo"/"Victor Hugo"、"歌剧魅影"/"Le Fantôme")。
- **结果列表**:命中项按类型分组(人物 / 作品),每项显示名称 + role/type + 缩略。虚构角色标 🎭。
- **无匹配**:提示"暂无 ta 的动线",不报错。

### 6.3 动线生成

选中一个实体后,后端(构建时预生成)按其关系拉出 POI 序列:

| 实体类型 | 动线 = 哪些 POI | 关系依据 |
|---|---|---|
| **真实 Person** | 其所有 person↔place 关系指向的 POI | frequented/lived_at/buried_at/designed/protested_against/commemorated_at |
| **虚构 Person** | 其 `fictional_setting` 取景 POI | lived_at(剧中) |
| **Work** | 其 set_in / depicts 的 POI + 作者的关联 POI | set_in/depicts + authored 链 |

- **排序**:多 POI 时按该城市棋盘 index 排序(即游戏动线顺序),保证动线在地图上顺畅。
- **只连已验证关系**:`verified:true` 且 sources≥2 才连线;查无实证的人-地关系不连(宁缺毋滥)。
- **单 POI 实体**:只高亮一个点 + 说明,不连线(如仅一处足迹的人物)。

### 6.4 地图呈现(复用 B 的内核)

动线本质是一条**临时故事线**,喂给 B 的同一套地图轨迹渲染器:

- POI 按序连成高亮轨迹线(直线段 + dasharray + 中点箭头),`flyTo` 逐点巡览。
- 每个 POI marker 弹出**该实体在此地的关系卡**:一句 note(准确措辞,取自 Relation)+ POI 名 + place_role 徽章。
- 虚构实体动线的点用 🎭 区分(走 fictional_setting 点),真实人物走 real_footprint/commemoration 点。
- 同一 POI 可同时出现在多个实体动线里(如先贤祠出现在雨果、伏尔泰、卢梭、居里夫人多条动线)。

### 6.5 与其他链路的接缝

| 从 | 到 | 触发 |
|---|---|---|
| 游戏模式「遇见的人」小卡 | 搜索动线 C | 点「查看 ta 的动线」,预填该人物 |
| 常规模式站点内容里的人名 | 搜索动线 C | 点人名(若为已验证 Person)跳 C |
| 搜索动线 C 的 POI marker | 常规模式 B | 点「在故事线里看这一站」跳 B 对应 stop |

### 6.6 边界

- **跨城市**:本期数据仅巴黎,动线只在巴黎;动线结构预留 `city_id`,多城时按城市分组。
- **虚实不混**:虚构角色动线只走虚构取景点,真实人物动线只走真实关联点,同一条动线内不混(数据上 `is_fictional` 分流)。
- **作品无地点**:若某 Work 无任何 set_in/depicts 且作者无关联 POI,搜索命中但提示"暂无地图动线",展示纯作品信息卡。

## 7. 常规模式(B):真实地图 + 故事线时间轴

### 7.1 显式导航(非滚动驱动)

storymap 不是 scrollytelling:它的 `IntersectionObserver` 只用于地图懒加载,章节切换靠**点击时间线节点 / 键盘 ←→ / 自动播放**。常规模式沿用此思路,`Scrollama` 依赖整个移除。对"想查资料的人",能直接跳到想看那站,优于被迫从头滚。

### 7.2 布局

```
桌面(≥1024px)                          移动(<1024px)
┌──────────┬─────────────────┐          ┌─────────────────┐
│ 时间轴    │                 │          │  地图 40% sticky │
│ 7 站(可点)│   真实地图       │          ├─────────────────┤
│          │   MapLibre      │          │ 站点内容(纵向滚)│
│ 当前站    │                 │          │ 时间轴顶部横胶囊 │
│ 五段式    │                 │          │                 │
└──────────┴─────────────────┘          └─────────────────┘
   34%          66%
```

### 7.3 五段式内容

每站展示该 POI 的五段式(沿用 v1 `narrative[]`):

| type | 标签 | 说明 |
|---|---|---|
| `scene` | 🎬 剧中场景 | 该地点在《艾米莉在巴黎》中的戏份 |
| `anecdote` | 💬 趣闻 | 现实轶事、争议 |
| `masterpiece` | 📖 名作 | 相关文学/艺术作品 |
| `history` | 🏛 历史 | 建筑/地名来历 |
| `practical` | 🧭 实用 | 开放时间、交通、机位 |

不是每站都有全 5 段(实际 3-4 段),**缺失段不渲染空标题**。站点内容里出现的**已验证人名**可点,跳搜索动线 C(§6.5)。

### 7.4 运镜(以 storymap 实测值为起点)

| 场景 | 动作 | 参数 |
|---|---|---|
| 进入带 `#stop=N` | `flyTo` | `duration:700, curve:1.4, speed:1.2, essential:true, zoom:15, pitch:0` |
| 进入无 hash | `fitBounds` 全景 | 7 站外接框 + `padding:60`, `duration:0` |
| 点时间线节点(相邻) | `flyTo` | `duration:700` |
| 点时间线节点(跨站) | `flyTo` | `duration:900` |
| 点 marker | `flyTo` + 脉冲 | + marker `pulse` 650ms |
| 点「全景」 | `fitBounds` | `duration:420` |
| 自动播放前进 | `flyTo` | `duration:1150`,站间停留 `clamp(dist_km×600, 1800, 3600)ms` |
| `prefers-reduced-motion` | `jumpTo` | 瞬时,但 `essential:true` 仍必带 |

**`essential:true` 硬要求**:不带则系统"减弱动态"会把 `flyTo` 静默降级为 `jumpTo`,运镜消失。

**轨迹线**:7 站按序连线,简化版直线段 + `line-dasharray`(不做 Catmull-Rom 平滑),走过实线、未到虚线,方向箭头在中点。

### 7.5 标记点状态

| 状态 | 表现 |
|---|---|
| `is-past` | 小圆点,淡墨,半径 6 |
| `is-active` | 大头针,河蓝色,半径 9,zIndex 高 |
| `is-future` | 小圆点,虚线描边,半径 6 |
| 日/夜分段 | 第 6、7 站带 🌙 角标,用 **board index** 与 `night_from_index` 比(非 `stop.order`) |

### 7.6 第三维 = 故事线切换 + 自动播放

不做对话人格(纯静态站无后端,编造问答踩内容真实性红线)。第三维改为:

- **故事线切换**:顶部胶囊条。本期 3 条线仅《艾米莉在巴黎》可用,另 2 条"规划中"不可点。
- **自动播放**:一键从第 1 站巡演到第 7 站,站间停留按真实地理距离动态计算(远则慢)。

### 9.1 游戏模式(A)

| 状态 | 读者 | 写者 | 持久化 |

```
position: N ─摇骰(1-6)→ min(N+roll, 11),逐格触发事件

turn:     idle ─点骰子→ rolling ─翻滚完→ playing ─事件播完→ idle
                                        └─遇卡片→ awaitCollect ─收卡→ playing
meetPerson: 落格且该格有未解识人物且 pendingSilhouette 空 → 候补;点亮→ metPeople+1,pending 清空
```
