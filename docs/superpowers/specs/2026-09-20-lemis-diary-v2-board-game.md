# Lemi's Diary v2 设计规格:大富翁玩法 + 双模式

## 1. 背景与问题

v1 已完成:三层数据模型、构建管线、7 个巴黎 POI(含精准配图与五段式内容)、纯静态站部署。

v1 的问题(实测):

| 检查项 | v1 实况 |
|---|---|
| 前端 JS 总量 | 141 行 |
| 地图镜头动画 | 0 个 |
| hover / 微交互 | 0 个 |
| 真正的交互 | 1 个(切故事线按钮) |
| 移动端媒体查询 | 0 个,侧栏写死 380px |

根因:把信息架构当成了产品设计。`7 POI × 5 字段 = 35 个信息块`码在侧栏,是数据库视角而非用户视角。

参考 storymap 的内核——把"一个人的一生"表达为 [空间轨迹] × [时间章节] × [可对话人格] 三个可联动维度——v1 只有空间一个维度。

## 2. 产品定义

> 一款"用大富翁玩法逛世界文化地标"的收集游戏,退出游戏还能当认真的文化地图查。

### 目标场景

| 场景 | 用户状态 | 需求 |
|---|---|---|
| 出发前躺着刷 | 做梦、种草 | 给幻想素材,让人想去 |
| 巴黎地铁上 | 碎片时间 | 快速给出此刻这里的谈资 |
| 站在花神门口 | 已到达 | 看到别人看不到的那一层 |

后两个场景是手机,因此 **mobile-first 是硬要求**,不是适配。

### 三层空间结构

```
世界地图(城市选择)
  └── 巴黎 · 3 条故事线 · SSR 卡待解锁
        └──《艾米莉在巴黎》棋盘   ← 首期实现
              └── 走格子 · 掉卡 · 集卡
```

### 双模式

| | 游戏模式(默认) | 图鉴模式 |
|---|---|---|
| 面向 | 想玩的人 | 想查资料的人 |
| 形态 | 骰子 + 棋子 + 掉卡 | storymap 式滚动叙事 + 镜头跟随 |
| 主线 | 走格子 | 故事线(storymap 的"人物"换成"故事线") |
| 切换 | 右上角按钮,随时互切 | 同左 |

两套共用同一份数据,差异只在表现层。

## 3. 核心规则

### 3.1 骰子控制"走多远",不控制"跳过谁"

摇到 N 则沿真实街道连续走过 N 格,途经的每个 POI 都触发掉卡,不跳过。

理由:数据中存在天然时间线(公寓"清晨拍绿门" → 亚历山大三世桥"日落最美" → 铁塔"夜间闪灯秀"),即 Emily 的一天。骰子若能跳过 POI,叙事完整性被破坏。骰子控制节奏而非内容。

### 3.2 棋盘构成

7 个 POI 之间填充路途格,首期共 **20 格**:

| 格子类型 | 数量 | 作用 |
|---|---|---|
| POI 格 | 7 | 掉 R 卡,核心内容 |
| 街头格 | 5 | 巴黎生活规则 / 城市运转 / 文化差异 / 冷知识 |
| 机会格 | 3 | 冷知识三选一 |
| 机位格 | 2 | 拍照机位推荐 |
| 彩蛋格 | 3 | 隐藏内容,掉 SR 卡 |

排布规则:POI 格按故事线既定顺序固定;路途格填充在相邻 POI 之间,数量按两站实际距离分配(距离远的多填)。棋盘首格为起点(Emily 的公寓),末格为终点(埃菲尔铁塔)。

### 3.3 一局 = Emily 的一天

时间随格子推进,**只分白天 / 夜晚两段**(不做多段渐变)。

切换点:棋子**首次抵达或越过第 13 格**(即亚历山大三世桥所在位置之后)时,地图底图切换为夜间样式,同时铁塔格进入"亮灯"状态。切换为一次性,不可逆,以 500ms 交叉淡入完成。

依据:该切换点对应数据中的天然时间线——亚历山大三世桥"日落时分金色雕塑最美",埃菲尔铁塔"夜间整点有 5 分钟闪灯秀"。一次切换比渐变更有记忆点,"天黑了"本身即是事件。

## 4. 卡池体系

| 卡 | 获取方式 | 巴黎首期 |
|---|---|---|
| R | POI 常规故事,落格必掉 | 7 张(每 POI 各 1) |
| SR | 彩蛋格触发 | 3 张 |
| SSR 碎片 | 跑完 1 条故事线 | 1 枚(共需 3) |
| SSR | 集齐 3 条线碎片合成 | 锁定(首期挂"待解锁") |

首期《艾米莉在巴黎》一条线共 **10 张可收集卡(7 R + 3 SR)**,卡册计数显示 `n/10`。SSR 不计入该分母,单独作为城市级奖励展示。

**只有 POI 卡(R)和彩蛋卡(SR)进卡册。** 机会格、机位格、街头格内容看完即走,不占卡位。

首期只做 1 条故事线跑通机制;SSR 挂"待解锁"作为明写的下一步钩子。

## 5. 交互与动效

### 5.1 主角

Lemi:戴牛仔帽、挎相机的小仓鼠。棋子形象。

### 5.2 一回合节拍(全程约 2.1 秒)

| 环节 | 时长 | 细节 |
|---|---|---|
| 摇骰子 | 500ms | 按下下沉 2px(100ms)+ 3D 翻滚(400ms,末段减速留悬念) |
| 背包步行 | ≤1000ms | Lemi 背包走过去,无附加小动作;格子多则走快 |
| 掉卡 | 600ms | 出片 150 + 显影 350 + 定影 100 |

### 5.3 镜头策略

- 步行时镜头**不动**,仅当棋子接近视野边缘 15% 时 `panTo` 一次
- **仅落 POI 格时 `flyTo` 俯冲**(pitch 50°),这是唯一的运镜时刻

依据:storymap 明确采用"只在出可视区才 panTo,绝不 flyTo/setBounds",以避免自动播放时的眩晕。少动换不晕。

### 5.4 掉卡与卡面

拍立得显影:模糊灰白 → 清晰彩色,边框光同步点亮。

稀有度边框:R 米白哑光 / SR 金色流光 / SSR 彩虹流光。

卡面排版:

```
[POI 实拍照片]
标题        ← 思源黑体
正文        ← 思源宋体
「经典台词」 ← 手写体,仅此一处,且可为空
```

手写体仅用于确有出处的经典台词/名言,无合格引语时该栏留白。

**收卡**:点任意位置收入卡册 → toast「已收入卡册」。无独立按钮、无飞入动效。

### 5.5 其他格子:统一 3 秒

| 格子 | 交互 |
|---|---|
| 机会格 | 三选一;3 秒倒计时,不答也自动翻面揭晓 |
| 机位格 | 机位实拍图 + 一句提示 |
| 街头格 | 一条街头卡 |
| 彩蛋格 | 特殊动效 + 掉 SR 卡(唯一超时者,因需收卡) |

### 5.6 已删除项

- 全部音效(不做任何音频)
- 落地震动
- 步行时的起伏 / 帽子 / 相机小动作
- 卡片飞入卡册动效
- 四段光照渐变

原则:动效只保留关键节点,避免杂乱。

## 6. 内容真实性机制

v1 内容为 LLM 生成 + LLM 自评置信度。该机制对描述性内容尚可,但对**引语**和**事实性规则**不足。

### 6.1 街头卡标准

| | 要求 |
|---|---|
| 可信 | 交叉验证通过即可(≥2 独立来源说法一致),不必官方出处 |
| 措辞准确 | 不把话说绝;有例外须写"部分/通常/多数" |
| 巴黎独有 | 换成其他城市不成立 |

第二条是实践中最易踩的坑。例:"地铁门要自己开"是错的(新车型自动),"**部分**地铁门要自己开"才对。

### 6.2 引语标准

需确切出处(剧集季集 / 书名页码 / 可查报道),须为原话而非转述,须能给出原文,且与该 POI 确有关联。任一不满足则该卡无手写体栏。

引语标准不随街头卡放宽——编造台词与说错规则的错误性质不同。

### 6.3 验证方式

**交叉验证 + 对抗性审查**,非学术级考据。对抗性审查可自动化:由子代理专门尝试证伪,挑不动的才留。比人工逐条查可行,比 LLM 自评可靠。

### 6.4 构建时 gate

- Quote:`verified != True` 或 `source` 为空 → 该 quote 字段不输出
- StreetCard:`verified != True` 或 `len(sources) < 2` → 该卡不输出

不接受 LLM 自评,只认审查通过的 `verified` 标记。"宁缺毋滥"卡死在构建时而非依赖自觉。

## 7. 数据模型

保留 v1 三层(POI / StoryStop / StoryLine / City),新增:

```python
@dataclass
class BoardTile:
    """棋盘格子。"""
    index: int              # 棋盘序号 0..N
    type: str               # poi|chance|photo|street|easter
    lat: float
    lng: float
    poi_id: str = ""        # type=poi 时指向 POI
    content_id: str = ""    # 其他类型指向对应内容


@dataclass
class Quote:
    """卡面手写体引语,带强制来源。"""
    text_zh: str
    text_original: str      # 原文,必填
    source: str             # 出处,必填
    source_url: str         # 必填
    verified: bool          # 审查通过才 True


@dataclass
class Card:
    """卡牌。"""
    id: str
    rarity: str             # R|SR|SSR
    storyline_id: str
    poi_id: str = ""
    image: Optional[ImageRef] = None
    title_zh: str = ""
    title_en: str = ""
    body_zh: str = ""
    body_en: str = ""
    quote: Optional[Quote] = None


@dataclass
class StreetCard:
    """街头卡。"""
    id: str
    category: str           # rule|transit|etiquette|trivia
    text_zh: str
    text_en: str
    near_poi_id: str        # 挂在哪两站之间
    sources: List[str]      # 交叉验证来源,≥2 条
    verified: bool
```

## 8. 卡册页面

全屏,入口为右下角带计数的卡册图标(如 `3/10`)。

- 按故事线分组展示
- **未获得卡显示剪影 + `?` 占位**,让用户看见还差什么(收集欲来源)
- 点卡片放大,可翻面重看
- SSR 位始终显眼锁定,显示进度 `1/3`

## 9. 图鉴模式

Scrollama.js 驱动的滚动叙事,主线为故事线。

- 滚到哪章地图 `flyTo` 到哪站
- 章节按白天 / 夜晚分两段
- **URL hash `#stop=3`** 记住当前站,刷新/分享可恢复
- 已收集卡在对应章节显示小角标(两模式进度互通)
- 移动端:地图收为顶部 40% sticky,文字在下方滚动

技术要点(已验证):

- Scrollama CDN:`<script src="https://unpkg.com/scrollama"></script>`,暴露全局 `scrollama`
- 用法:`scrollama().setup({step:".step"}).onStepEnter(cb)`
- 依赖 IntersectionObserver;**CSS 勿用 vh 单位**(滚动触发 resize);移动端 offset 用 px
- **依赖整页滚动,不能置于 iframe**

## 11. 移动端

竖屏布局:

```
┌─────────────┐
│   地图 55%   │  ← 棋盘
├─────────────┤
│ 白天/夜晚指示 │
│ 骰子 + 卡册   │  ← 拇指热区
└─────────────┘
```

- 卡片弹出走底部抽屉上滑,占满屏
- 骰子按钮置于右下拇指热区
- 触控目标 ≥ 44px

## 12. 无障碍与降级

- `prefers-reduced-motion`:所有动效退化为 200ms 淡入淡出,骰子直接出点数
- MapLibre `flyTo` 须带 `essential: true`,否则 reduced-motion 下会被降级为 jumpTo
- 键盘可操作:骰子、卡片、模式切换
- 切站时 `aria-live` 播报当前站

## 13. 技术约束

- 纯静态站,无后端、无账号
- 原生 JS + MapLibre GL,CDN 引入,无构建工具
- Python 构建管线(标准库 + requests)
- 单人开发

## 14. 实施顺序

1. **先跑通游戏机制**(棋盘、骰子、步行、掉卡、卡册)
2. 图鉴模式
3. **内容审计作为独立后置步骤**(交叉验证 + 对抗性审查)

先验证玩法再批量产内容,避免玩法不对味导致内容返工。

## 15. 已知取舍

| 取舍 | 代价 | 换来 |
|---|---|---|
| 骰子不跳过 POI | 随机性减弱 | 叙事完整 |
| 步行不跟镜头 | 少了运镜感 | 不眩晕 |
| 首期 1 条故事线 | SSR 拿不到 | 先验证机制 |
| 无音效 | 少一个感官通道 | 省掉音频资源/自动播放策略/开关 UI |
| 双模式 | 工作量翻倍 | 玩家与查资料者都接住 |
